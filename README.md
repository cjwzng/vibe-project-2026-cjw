# IBK 사이트 구현 프로젝트

> **이 문서는 코드를 작성·수정하는 모든 에이전트가 가장 먼저 읽는 문서다.**
> 상세 규약은 `spec-kit/AGENTS.md`에 있고, 이 문서는 그 문서로 안내하며 시작 전에 알아야 할 핵심만 요약한다.

---

## 0. 시작 전 필독 순서

1. **`task-history/task.md`를 먼저 읽어** 이전 작업 내용과 현재 진행 상태를 확인한다. 완료된 작업을 중복 수행하지 말고, 새 요청에 맞는 후속 작업만 진행한다. 작업을 마치면 필요한 경우 이 파일의 요약도 갱신한다.
2. **`spec-kit/AGENTS.md`를 처음부터 끝까지 읽는다.** 특히 아래 부분을 놓치지 않는다.
   - **PART 3** — 이 사이트 전용 규칙 (박스 구조, 수치, 글자, 색상, 반응형)
   - **PART 4** — 작업 완료 전 체크리스트
3. `css/tokens.css`와 기존 컴포넌트가 있으면 먼저 읽고, 비슷한 것을 새로 만들지 않는다.
4. 요청 범위를 확인한다. 범위 밖 파일은 수정하지 않는다.
5. 명세에 없거나 값이 `미확정`이면 **임의로 정하지 말고** 가정을 적어 질문한다.

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 타겟 사이트 | https://www.ibk.co.kr/ |
| 구현 원칙 | **시각 디자인은 원본과 동일**, **내부 레이아웃은 단순화된 구조로 새로 구성** |
| 스택 | HTML5 / CSS3 / Vanilla JavaScript (ES2022+), 프레임워크·빌드 도구 없음 |
| 언어 | 한국어 UI (`<html lang="ko">`) |

- 원본 사이트는 자동 접근이 차단되어 있다. 값은 `spec-kit/AGENTS.md` PART 3에 정리된 것만 기준으로 삼고, **사이트 값을 추정해서 채우지 않는다.**
- 공지사항 게시판은 `#/notice`에서 목록·상세·쓰기·수정 화면을 제공한다. 데이터는 비동기 `noticeService` 계층을 통해 namespaced localStorage에 저장하며, Firebase 전환 시 서비스 진입점과 저장소 구현체를 교체한다.
- 상단 Notice 안내 바는 스크롤 중 상단에 고정되며, 닫기 버튼으로 현재 페이지에서 숨길 수 있다.
- 카드 쇼핑은 `#/cards`, `#/card/{id}`, `#/cart` 경로에서 제공한다. 상품 원본은 `data/recommended-cards.json`이며 초기 진입 시 카탈로그와 장바구니를 비동기 서비스로 localStorage에 저장한다.

## 2. 문서 위치와 우선순위

```
/
├─ README.md              ← 지금 이 문서 (진입점)
├─ task-history/
│  └─ task.md             ← 이전 작업 요약과 다음 작업 안내
├─ spec-kit/
│  └─ AGENTS.md           ← 디자인·개발 규약 (살아있는 문서)
├─ index.html
├─ pages/
├─ assets/ (images, icons, fonts)
├─ css/ (tokens, base, layout, components, utilities, main)
└─ js/ (main.js, modules, utils, config.js)
```

규칙이 충돌하면 아래 순서를 따른다.

```
접근성·보안  >  사용자 요구 명세  >  AGENTS.md  >  성능  >  개인 취향·관습
```

`AGENTS.md` 안에서는 **PART 3(사이트 전용)이 PART 1·2(일반)보다 우선**한다. 단, 접근성·보안은 PART 3보다도 앞선다.

## 3. 반드시 지킬 핵심 규칙 (요약)

**레이아웃 구조**
- 페이지 골격은 **`header + (main > section) + footer`** 로 고정한다.
- 박스는 **겉박스 > `.inner-box` > 파티션** 3단계만 쓴다. 겉박스 안에 겉박스, 속박스 안에 속박스를 넣지 않는다.
- `.inner-box`는 `max-width` + 중앙정렬이다. 메인 1000px, 헤더·푸터는 `.inner-box--narrow`(940px). 이름은 `.inner-box`로 통일한다 (`.container`, `.wrapper` 등 금지).
- 파티션은 **flex**가 기본이다. 줄바꿈이 필요할 때만 `.partition--wrap`을 쓴다. **파티션에 Grid를 쓰지 않는다.** 2차원 배치는 파티션 안쪽 내용박스에서만 `grid`를 쓴다.

**값과 스타일**
- 색·글자·간격·그림자·라운드는 모두 `css/tokens.css`의 변수로만 쓴다. 하드코딩은 금지다.
- 서체는 `IBKiDreamL`(본문)과 `IBKiDreamB`(제목)이다. **폰트 파일이 아직 없으므로 `@font-face`를 만들지 않고** 폴백 스택(`Arial, 'Noto Sans KR', sans-serif`)만 쓴다.
- 사이트 색 중 대비가 부족한 두 개는 보정값을 쓴다. `#0082c1` → `#007dba`, `#f2631b`(글자용) → `#cd4d0c`.
- 사이트의 `* { font-family: ... !important }`, float 배치, 카드의 absolute 배치는 가져오지 않는다.

**공통 금지**
- 인라인 `style`·이벤트 속성, `id` 선택자, `!important`, `var`, `console.log` 잔존
- `innerHTML`에 사용자·외부 입력 삽입
- 요청하지 않은 라이브러리·CDN·폰트 추가
- `<div>`·`<span>`에 클릭 이벤트 부여 (버튼은 `<button>`, 이동은 `<a>`)

## 4. 시작 시 확인할 미확정 항목

아래는 아직 값이 없다. 해당 작업이 나오면 **임의로 만들지 말고 사용자에게 요청**한다.

- IBKiDream 폰트 파일과 라이선스
- GNB 메뉴(원본은 이미지)의 글자 크기·색, 전체 메뉴 수치
- 상태색 (성공·경고·오류·정보), 폼 오류 표시
- 768~959px 구간의 메인 콘텐츠 세부 값
- 서브페이지용 폼·표·페이징 수치

값이 확정되면 `spec-kit/AGENTS.md`의 표를 먼저 고치고 변경 이력에 기록한다.

## 5. 작업 방식

- **재사용 우선, 최소 변경**: 있는 토큰·컴포넌트를 쓰고, 요청받은 범위만 고친다.
- **규약이 막히면**: 규약을 지킨 대안을 제시한다. 사용자가 명시적으로 위반을 원하면 사유를 코드 주석과 보고에 남긴다.
- **규약에 없는 상황이면**: 기존 코드의 패턴을 따르고, 새 패턴을 만들었다면 `AGENTS.md`에 추가할 항목을 제안한다.
- 커밋은 하나의 논리적 변경 단위로 하고 Conventional Commits(`feat:`, `fix:`, `style:` …)를 쓴다.

## 6. 확인 방법

- 검수 뷰포트는 **360 / 390 / 768 / 1024 / 1440px**이고, 가로 스크롤이 생기면 안 된다.
- 사이트 전환 경계도 함께 본다. 767·768px(메인), 959·960px(헤더·푸터), 1200px(배경 이미지)이다.
- 키보드만으로 모든 기능을 쓸 수 있어야 하고, 포커스 표시가 보여야 한다.
- 완료 전 `AGENTS.md` **PART 4 체크리스트**를 모두 통과시킨다.
