## 히어로 섹션 반응형 웹 구현

첨부한 이미지 2장은 순서대로 데스크탑과 모바일의 화면입니다.
두 이미지를 분석하여 레이아웃, 요소 배치, 크기, 간격, 타이포그래피를 최대한 유사하게 구현해주세요
## Hero Section – Responsive Layout Specification

### 1. Desktop Layout (기본 레이아웃)
- 상단 헤더 아래에 히어로 섹션을 배치한다.
- 히어로 영역은 좌우 2단 구조로 구성한다.
  - 좌측: 로그인 버튼, 인증센터 버튼, 메인 카피, 제목, 상세보기 링크.
  - 우측: 메인 비주얼 이미지(캐릭터 및 인증서 그래픽).
- 텍스트 영역은 좌측 정렬, 메인 비주얼은 우측 정렬한다.
- 메인 비주얼은 원본 비율을 유지하며 충분한 크기로 표시한다.
- 전체 히어로 영역은 넓은 여백을 확보하고 수평 중심으로 균형 있게 배치한다.
- 슬라이드 페이지 표시 및 이전/다음/일시정지 컨트롤은 우측 상단에 배치한다.

### 2. Mobile Layout (모바일 레이아웃)
- 데스크톱의 2단 구조를 세로형 단일 컬럼 구조로 변경한다.
- 콘텐츠 순서는 다음과 같이 유지한다.
  1. 상단 헤더 (중앙 로고, 우측 전체메뉴 햄버거).
  2. 로그인 및 인증센터 버튼.
  3. 메인 카피와 제목, 상세보기 링크.
  4. 메인 비주얼 이미지.
  5. 주요 서비스 바로가기 메뉴.
- 텍스트 영역은 좌측 정렬을 유지한다.
- 메인 비주얼은 텍스트 아래에 배치하고 화면 중앙에 정렬한다.
- 이미지 크기는 모바일 화면에 맞게 축소하되 원본 비율을 유지한다.
- 텍스트와 이미지 사이에는 충분한 세로 간격을 확보한다.
- 서비스 바로가기 메뉴는 데스크톱의 가로 1열 구조에서 모바일 2열 배치로 변경한다.

### 3. Responsive / Media Query Rules

**브레이크포인트: 768px**

- Desktop: 769px 이상
- Mobile: 768px 이하

데스크톱을 기본 레이아웃으로 구현한 후 CSS Media Query를 통해 모바일 레이아웃으로 전환한다.

```css
/* Desktop: 기본 레이아웃 */
.hero {
  display: flex;
  flex-direction: row;
  align-items: center;
  justify-content: space-between;
}

.hero-content {
  width: 50%;
}

.hero-visual {
  width: 50%;
}

/* Mobile: 768px 이하 */
@media screen and (max-width: 768px) {
  .hero {
    flex-direction: column;
    align-items: stretch;
  }

  .hero-content {
    width: 100%;
    text-align: left;
  }

  .hero-visual {
    width: 100%;
    display: flex;
    justify-content: center;
  }

  .hero-visual img {
    max-width: 100%;
    height: auto;
    object-fit: contain;
  }
}
```

### 4. 구현 시 핵심 원칙
- 모바일은 데스크톱 화면을 단순 축소하는 방식이 아니라 별도의 레이아웃으로 재구성한다.
- 동일한 콘텐츠와 이미지 에셋을 재사용하되 화면 크기에 따라 배치, 정렬, 간격, 크기를 변경한다.
- 불필요한 중복 DOM 생성을 지양하고 CSS Media Query 중심으로 반응형을 구현한다.
- 이미지 비율이 왜곡되거나 화면 밖으로 넘치지 않도록 한다.
- 768px 경계에서 레이아웃이 깨지지 않도록 확인한다.
- 320px ~ 768px 구간에서도 가로 스크롤이 발생하지 않도록 한다.
- 데스크톱과 모바일 모두 제공된 레퍼런스 이미지의 시각적 구성과 콘텐츠 순서를 최대한 일치시킨다.

# 전체 메뉴(Global Navigation) 구현 명세

제공된 데스크톱 및 모바일 레퍼런스 이미지를 기준으로 전체 메뉴 기능을 구현한다.

## 1. 공통 동작 규칙

- 데스크톱과 모바일은 서로 다른 메뉴 UI와 애니메이션을 사용한다.
- 화면 너비에 따라 메뉴 유형을 전환한다.
- 데스크톱: 전체 메뉴 버튼 클릭 시 전체 메뉴 패널 표시.
- 모바일: 우측 상단 햄버거 버튼 클릭 시 사이드 메뉴 표시.
- 메뉴가 열려 있을 때 배경 페이지 스크롤을 방지한다.
- 메뉴 닫기 버튼 및 배경 오버레이 클릭 시 메뉴를 닫는다.
- 메뉴가 열려 있는 동안 배경 콘텐츠는 비활성화한다.
- ESC 키 입력으로 메뉴를 닫을 수 있도록 한다.
- 메뉴 열기와 닫기 상태는 명확하게 관리하고 중복 클릭에 따른 애니메이션 충돌을 방지한다.

## 2. Desktop 전체 메뉴

### 화면 구성
- 기존 데스크톱 헤더 바로 아래에 전체 메뉴 패널을 표시한다.
- 전체 메뉴 패널은 화면 가로 전체 너비를 사용한다.
- 패널 배경은 연한 블루 계열(#F4F8FD 또는 유사 색상).
- 메뉴 콘텐츠는 중앙 정렬된 고정 최대 너비 컨테이너 안에 배치한다.
- 메뉴 항목은 가로 7개 컬럼으로 구성한다.
- 각 컬럼은 세로 구분선으로 구분한다.
- 컬럼 내부에는 파란색 계열의 대분류 제목과 작은 글씨의 하위 메뉴를 세로로 배치한다.
- 금융상품 및 금융서비스처럼 하나의 컬럼 안에 여러 그룹이 있는 경우 그룹 간 적절한 간격을 둔다.
- 패널 오른쪽 상단에 X 아이콘과 '닫기' 텍스트를 배치한다.

### 표시 애니메이션
- 전체 메뉴 버튼 클릭 시 패널이 자연스럽게 Fade In 되면서 나타난다.
- 닫기 버튼 클릭 시 Fade Out 되면서 사라진다.
- 애니메이션 시간은 약 250~300ms.
- opacity와 visibility를 활용하여 자연스럽게 전환한다.
- 메뉴가 닫힐 때 레이아웃 공간을 남기지 않도록 한다.

## 3. Mobile 전체 메뉴

### 화면 구성
- 브레이크포인트 768px 이하에서 모바일 전용 메뉴를 사용한다.
- 모바일 헤더의 오른쪽 상단 햄버거 버튼을 클릭하면 사이드 메뉴가 열린다.
- 화면 오른쪽에서 왼쪽 방향으로 슬라이딩하며 등장한다.
- 사이드 메뉴 너비는 약 320px이며, 작은 화면에서는 화면 너비의 85%를 넘지 않도록 한다.
- 메뉴 패널은 화면 오른쪽에 고정하고 화면 높이 전체를 사용한다.
- 메뉴 패널 배경은 흰색이다.

### 모바일 메뉴 내부 구조
1. 상단 영역
   - 파란색 계열의 배경.
   - 상단에 금융사기예방센터, 고객센터, 은행소개, 영업점 안내, Global 등의 링크 배치.
   - 우측 상단에 X 닫기 버튼 배치.
   - 하단에 검색 입력창과 검색 버튼 배치.
2. 브랜드 영역
   - 파란색 배경의 IBK기업은행 브랜드 영역.
   - 로고 또는 브랜드 텍스트 중앙 정렬.
3. 메뉴 목록 영역
   - 개인뱅킹
   - 기업뱅킹
   - 금융상품
   - 금융서비스
   - 금융정보
   - 카드
   - 고객센터
   - 금융사기예방센터
   - 각 메뉴는 가로 전체 너비를 사용하는 세로 목록으로 배치한다.
   - 메뉴 사이에 얇은 회색 구분선을 표시한다.
   - 하위 메뉴가 있는 항목은 오른쪽에 파란색 화살표 아이콘을 표시한다.
   - 메뉴 선택 시 하위 메뉴를 확장하거나 해당 메뉴로 이동할 수 있도록 구현한다.

### 표시 애니메이션
- 햄버거 버튼 클릭 시 배경에 반투명 검정색 오버레이를 표시한다.
- 오버레이는 opacity Fade In 효과를 적용한다.
- 사이드 메뉴는 오른쪽 바깥 영역에서 화면 안쪽으로 Slide In 한다.
- X 버튼 클릭 시 사이드 메뉴는 오른쪽 바깥으로 Slide Out 한다.
- 오버레이도 동시에 Fade Out 된다.
- 애니메이션 시간은 약 300ms.
- 메뉴가 열려 있을 때 본문 영역은 어둡게 처리하고 클릭할 수 없도록 한다.

## 4. Responsive Media Query

브레이크포인트는 768px을 기준으로 한다.

- Desktop: 769px 이상
- Mobile: 768px 이하

```css
/* Desktop */
@media screen and (min-width: 769px) {
  .desktop-global-menu {
    display: block;
  }

  .mobile-global-menu {
    display: none;
  }
}

/* Mobile */
@media screen and (max-width: 768px) {
  .desktop-global-menu {
    display: none;
  }

  .mobile-global-menu {
    display: block;
  }
}
```

## 5. 기술적 구현 지침

- React 기반이라면 메뉴 열림 상태를 state로 관리한다.
- 메뉴 열기와 닫기는 독립적인 이벤트 핸들러로 구현한다.
- CSS Transition을 사용하여 Fade 및 Slide 애니메이션을 구현한다.
- 메뉴가 닫히는 애니메이션이 완료되기 전 DOM을 즉시 제거하지 않는다.
- 메뉴의 표시 상태와 애니메이션 상태를 구분하여 관리한다.
- 메뉴가 열릴 때 body에 overflow: hidden을 적용하고 닫힐 때 원상 복구한다.
- 모바일 사이드 메뉴는 position: fixed와 transform: translateX()를 활용한다.
- 데스크톱 전체 메뉴는 헤더 아래에 배치하고 position 및 z-index를 적절하게 설정한다.
- 메뉴 패널과 오버레이의 z-index 계층을 명확하게 관리한다.
- 키보드 접근성을 위해 버튼에는 aria-expanded, aria-controls, aria-label을 적용한다.
- 메뉴가 열릴 때 포커스를 메뉴 내부로 이동하고 닫힐 때 기존 버튼으로 복귀시킨다.

## 6. 구현 및 검수 기준

- 데스크톱 전체 메뉴는 Fade In / Fade Out 방식으로 동작해야 한다.
- 모바일 전체 메뉴는 우측 Slide In / Slide Out 방식으로 동작해야 한다.
- 데스크톱과 모바일 메뉴가 동시에 표시되면 안 된다.
- 메뉴가 열린 상태에서 브라우저 너비가 768px 경계를 넘으면 메뉴 상태를 안전하게 초기화하거나 해당 화면에 맞게 전환한다.
- 메뉴가 닫힌 뒤 오버레이가 남거나 본문 스크롤이 잠긴 상태로 유지되면 안 된다.
- 메뉴 열기와 닫기를 반복해도 화면이 깨지지 않아야 한다.
- 레퍼런스 이미지의 메뉴 컬럼 수, 메뉴 순서, 색상, 간격, 정렬을 최대한 동일하게 구현한다.
- 데스크톱 및 모바일 실제 화면 크기에서 각각 검수한다.

**중요:** 데스크톱과 모바일은 단순한 크기 변경이 아니라 메뉴 구조와 인터랙션 방식 자체가 다른 별도 UI로 구현한다. 제공된 두 레퍼런스 이미지를 각각의 기준 디자인으로 삼는다.
