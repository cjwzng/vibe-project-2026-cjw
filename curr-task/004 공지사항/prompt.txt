[공지사항 게시판 프롬프트]
- 첨부: 게시판 각 화면(4가지)
- 프롬프트(원본): 
첨부된 화면과 동일하게 공지사항 게시판을 만들거야. DB없이 로컬스토리지로 개발할거야.
개발후 파이어베이스 DB로 마이그레이션 할 예정이야. 따라서 localstorage_to_firebase_guidelines_md.md
파일 지침에 따라 개발 구현해야해.

-프롬프트(수정:클로드)
첨부된 4개 화면(목록, 상세, 글쓰기, 글수정)과 동일한 UI로 IBK기업은행 공지사항(NOTICE) 게시판을 구현해줘.

[개발 방식]
- DB 없이 브라우저 localStorage만 사용해 개발한다.
- 개발 완료 후 Firebase(Firestore)로 마이그레이션할 예정이므로, 반드시 localstorage_to_firebase_guidelines_md.md 지침에 따라 구현한다.
- 데이터 접근 코드는 별도 저장소 계층(repository/service)으로 분리한다. UI 컴포넌트에서 localStorage를 직접 호출하지 않고, 저장소 함수만 호출한다.
- 저장소 함수는 모두 async(Promise 반환)로 작성한다. 그래야 Firebase 전환 시 UI 코드를 수정하지 않는다.

[화면 및 기능]
1. 목록: 총 게시물 수, 번호/제목/등록일/조회수 테이블, "공지" 배지, 페이지네이션(10개 단위, 처음/이전/다음/끝), 검색(전체 + 제목 키워드), 글쓰기 버튼
2. 상세: 제목, 등록일, 조회수, 본문, 목록으로/수정/삭제 버튼. 진입 시 조회수 +1
3. 글쓰기: 제목(필수), 내용(필수, 간단한 에디터), 첨부파일(최대 10MB, JPG/PNG/PDF), 취소/등록
4. 글수정: 기존 값 채움, 취소/수정
5. 삭제: 확인창 후 삭제, 완료 시 목록으로 이동
6. 공통: 상단 헤더/메뉴, 브레드크럼(홈 > 홍보센터 > 공지사항), NOTICE 타이틀 영역은 첨부 화면과 동일하게 구성

[데이터 모델]
notice { id, no, title, content, isNotice, attachments[], createdAt, viewCount, updatedAt }
- id는 문자열 고유값(UUID)으로 생성한다 (Firestore 문서 ID와 호환).
- 날짜는 ISO 문자열로 저장하고, 화면 표시 때만 YYYY.MM.DD로 변환한다.
- 첨부파일은 메타데이터(파일명, 크기, 타입)만 저장한다. 실제 파일은 추후 Firebase Storage로 이관한다.

[기타]
- 초기 데이터로 첨부 화면의 샘플 게시물 7건을 시드한다.
- 입력값 검증(필수값, 파일 용량/확장자)과 빈 목록 상태 처리를 포함한다.
- 완성 후 마이그레이션 시 교체해야 할 파일/함수 목록을 요약해서 알려준다.

수정한 부분

화면 4종(목록/상세/글쓰기/글수정)과 기능을 명시해서 첨부 이미지와 빠짐없이 맞추도록 했습니다.
마이그레이션을 쉽게 하는 핵심 조건을 추가했습니다. 저장소 계층 분리, async 함수, 문자열 ID, ISO 날짜입니다.
첨부파일은 로컬스토리지 용량 한계 때문에 메타데이터만 저장하도록 했습니다.
지침 md와 충돌하지 않도록 세부 구현은 최소화하고 "지침 우선"으로 정리했습니다.

지침 md에 저장소 인터페이스나 컬렉션명 규칙이 따로 있다면, 그 규칙이 이 프롬프트의 데이터 모델보다 우선하도록 하세요.
